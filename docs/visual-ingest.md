# B 站画面优先导入

数据库升级：备份 PostgreSQL 后运行 `python -m scripts.migrate_video_metadata`。
002 只为切片增加可空的来源列，旧切片继续使用原来源。

添加攻略视频 → 填入 BV 号按回车预览 → 点击「解析整条视频」。已入库视频也可以点击详情里的「继续解析全片画面」。
本地文件和聊天补查保持原流程。

- API 字幕直接用于口述索引，不替代配队卡等画面证据。
- 视频时长确定后，从 0 秒到结尾自动分段（通常 45 秒，特别短的尾段并入上一段）。
  截片按目标起点重编码，校验优先使用视频轨时长，不把容器关键帧预滚计入判断；仍保留时长容差和片段大小限制。
- Whisper 局部转写在向量化前做保守的专名校对：标题明确写出名字，且同一视频已经处理的硬字幕、画面文字或 API 字幕有相同写法时，才检查口述的属性描述是否出现同音错名。不是全局替换，也不从标题补充事实。校对前的简体转写保存在 `chunks.original_text`，只索引校对后的正文。

- 用户在任务页只确认一次，才从头到尾把剩余段的静音画面分别发给百炼。拒绝或约 3 分钟未确认就不上传，已入库字幕不受影响。
  Qwen 只提取可回看证据，区分硬字幕识读与画面解读。
- API 字幕或硬字幕覆盖足够时不重复转写；否则仅在本地检测到可能人声时，Whisper 才补充同段音频。
- 逐段写入索引和完成状态；失败不阻断后续片段。再点「继续解析全片画面」只跑失败或未检查的段。
  云端请求失败不会变成全片转写。所有临时样本处理后清理，已保存字幕和向量不会被覆盖。

已有 Docker 数据库首次启用这个功能前，在项目根目录执行一次（只加列，不改旧切片）：

```bash
docker exec -i video-rag-pg sh -c 'psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < deploy/migrations/004_chunk_original_text.sql
```

云端配置沿用对照实验的 `DASHSCOPE_API_KEY`、`DASHSCOPE_WORKSPACE_ID`、
`DASHSCOPE_REGION`，不启用搜索。模型输出不是逐字校验后的字幕，重要角色名请通过引用回看原片。

排查百炼问题时，在后端 Uvicorn 日志按任务 ID 或页面中的请求编号过滤：
`await_headers` 表示尚未收到 HTTP 响应头（无法进一步确定是连接、上传还是服务首响阶段），
`headers` 会记录 HTTP 状态，`read_stream` 表示已收到响应头、正在读回复。
日志只记录阶段、大小、耗时、事件数和异常类型，不写密钥、地址、请求内容或模型输出。
百炼请求分别设置连接、写入和读取超时（15 秒、60 秒、120 秒），其中写入超时针对发送数据时的等待，并非整次请求的总时限。
